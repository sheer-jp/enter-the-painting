# 作業ルーチン

「作ったら、確かめて、残す」を毎回やる。短時間でもこの順番を崩さない。

## 作業の始め方（2 分）

1. `docs/LOG.md` の一番上の「次にやる」を読む
2. 今回やることを 1〜3 個に絞る。`docs/SCHEDULE.md` の当日ゴールと照らす
3. 作品の体験に関わる変更なら、`docs/USERS.md` の「誰のどの悩みに効くか」を 1 行で言えるか確認する

## 作業の終わり方（`/close`、10 分）

1. **テスト**：`npm test`（単体）と `npm run smoke`（ブラウザ起動確認）。落ちたら直すか、理由をログに書く
2. **レビュー**：`/code-review` を差分に対して実行し、指摘を直すか、直さない理由をログに書く
3. **ログ**：`docs/LOG.md` に「やった / 決めた / 困った・学んだ / 次にやる」を追記
4. **コミット・push**：日本語の 1 行メッセージ。`main` に直接でよい（1 人開発のため）

テストが未整備の間（Day 1 前半）は 1 を「ブラウザで開いて動くことを目で見る」に置き換える。それもログに書く。

## レビューの観点

Claude が `/code-review` で見る。人間（作家）は体験だけ見ればよい。

- `CLAUDE.md` の作業ルールに反していないか（絵を変えない、流体・文字・音をモードで分岐しない、ユーザー操作内で音声・XR を開始、性能上限）
- 空間モードと物語モードのどちらかを壊していないか。フォールバック（静止画モード）が生きているか
- `space.json` の形を変えたなら `docs/WORK_FORMAT.md` も変えたか
- 依存を増やしたなら `docs/ARCHITECTURE.md` に理由を書いたか

## テストの層

| 層 | 何を | どうやって | いつ |
| --- | --- | --- | --- |
| 単体 | 生成パイプライン（k-means、流れ場、space.json の形、言語コードの正規化、翻訳キャッシュの鍵） | vitest。小さな合成画像（単色・2 色・グラデーション）で期待値を固定 | `/close` のたび |
| スモーク | 作品ページが開き、「入る」で物語モード T0 が出る。コンソールエラー 0。WebGL を無効にしても静止画モードで通る | Playwright（headless Chromium）。dev では `?w=sample` | `/close` のたび |
| 実機 | 3 環境で実際に入れるか | 下のチェックリストを手で | 毎日 1 回は必ず。Day 3 以降は Quest を含める |

### 実機チェックリスト（`docs/LOG.md` に結果を書く）

| 端末 | 確認 |
| --- | --- |
| PC（Chrome） | 作品ページ → 「入る」→ 物語モード T0〜T5 が無操作で通る。クリックで一時停止、Esc で閉じる |
| iPhone（Safari） | 音の許可 → 声が鳴る。縦・横で文字が読める。タップで一時停止。QR から 30 秒以内 |
| Android（Chrome） | 同上 |
| Quest（ブラウザ） | 「VR で入る」→ S1 壁の実寸の絵 → トリガーでギュン → S2 シュワシュワ → S3 全方向に色 → S4 文字が読める → B / Y で戻る。72fps |
| 共通 | 英語設定の端末で英語。作品ページが 2 秒で絵。SNS に貼ると絵が出る。部屋で見るが実寸に見える |

## 作品を追加するときのチェック

1. `works/<id>/` に画像・`work.json`・音声を置く
2. `npm run generate -- <id>` が通る
3. 単体テストが通る（生成物の形が崩れていない）
4. 作家本人が PC で見て「自分の絵の中だ」と感じるか 1〜5 で記録（`docs/USERS.md` の記録欄）
5. 納得いかなければ `overrides` で詰める。詰めた値と理由をログに書く
