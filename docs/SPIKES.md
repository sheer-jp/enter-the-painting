# 技術検証（最初に潰す不安）V2

計画が崩れる可能性が高い順。各項目は「2〜3 時間で白黒つける」小さな実験。失敗したら逃げ道に切り替え、`docs/CHANGELOG.md` に書く。

| ID | 不安 | 検証のしかた | 合格 | 逃げ道 | いつ |
| --- | --- | --- | --- | --- | --- |
| S-1 | GPU 流体シムを three.js 上で自前実装できるか。絵の構図が流れても残るか | 速度場 256、色 1024 の ping-pong。移流・渦度・圧力（Jacobi 20 回）。絵を色の初期値に、`flow.png` を速度に | PC で 60fps。10 秒後も主要色と構図が見分けられる（作家判定） | 流体をやめ、流れ場に沿う粒子（GPGPU、2,000 個）+ 絵のゆらぎシェーダに落とす | Day 1 午前 |
| S-2 | troika-three-text で日本語・中国語・韓国語が出るか。フォントが重すぎないか | Noto Sans JP をサブセット（使う文字だけ）して 40 文字を表示。zh / ko も 1 行ずつ | 崩れない。サブセットで 300KB 以下。VR で 2m 先の 12cm が読める | Canvas 2D でテキストを描いてテクスチャにする（スプライト）。にじむが動く | Day 2 午前 |
| S-3 | Quest のブラウザで流体シム + 球面で 72fps 出るか | S-1 の結果を球面に貼り、WebXR セッションで性能表示を見る | 72fps（Quest 2）。落ちても 60 以上 | 速度場 128、色 512、圧力 8 回。それでも駄目なら流体は 2D の映像にし、VR は「平面の絵がふくらんで包む」だけに | Day 3 午前 |
| S-4 | iOS Safari で音声・フォント・流体が「入る」後に正しく始まるか | iPhone で作品ページ → 「入る」 → T0〜T3 | 声が鳴る。WebGL2 で流体が動く | WebGL1 フォールバック（half float の確認）。音は `<audio>` 要素に切り替え | Day 2 夕方（簡易）、Day 5（本番） |
| S-5 | 部屋の画像に絵を射影で貼って自然に見えるか | 1 部屋で `sharp` の affine または自前の射影（4 点）。影を薄く | 作家が「自分の絵のまま」「不自然でない」 | 正面の壁だけの部屋画像に限定し、アフィン（拡縮のみ）で貼る | Day 4 午前 |
| S-6 | GitHub Pages で `/w/<id>/` の静的ページと OGP が効くか | 1 ページをデプロイし、X / LINE のカードプレビューで確認 | 絵とタイトルが出る | Cloudflare Pages に切り替え（同じ静的出力） | Day 4 夕方 |
| S-7 | Claude API の翻訳が詩的な文で崩れないか | 1 作品のメッセージを ja + en から fr / zh-Hans に訳し、母語話者 1 人に読んでもらう | 「直訳っぽくない」 | 英語を作家が丁寧に書き、英語からだけ訳す。駄目な言語は落とす | Day 6 午前 |
| S-8 | 作品ページが 4G で 2 秒以内に絵を出せるか | Chrome の throttling（Fast 3G / 4G）で `/w/<id>/` を計測 | 絵 2 秒、「入る」5 秒 | 絵を 800px に、JS を `defer` から `lazy` に、流体を「入る」後に import | Day 4 夕方 |
