## 2026-11-03（Day 1〜2）

**やった**
- 作家の決定を記録：落とすもの（U-12）、`sheerarts.com` のサブドメイン（U-13）、会場に Quest 1 台（U-14）。最初の作品 harmoney を `works/` に
- 生成パイプライン `scripts/generate/`：縮小、k-means 主要色、構造テンソルの流れ場 `flow.png`、翻訳キャッシュ（原文のハッシュ）、部屋のホモグラフィ合成、space.json、QR、作品カード、作品ページとギャラリーの HTML。Claude API での翻訳と物語の下書き（キーがあるときだけ）
- GPU 流体 `src/fluid/`：等距離円筒 2:1、MacCormack 移流 + 原画への回帰、渦度、圧力、シュワシュワ（縁からの泡）、品質 3 段階
- 物語モード `src/story/`：T0〜T5、画面の奥から浮く文字（DOM）、声は `<audio>`、環境音・泡・ドローンは Web Audio で合成、一時停止・次へ・閉じる、静止画フォールバック、`?from=qr` の一言
- VR 空間モード `src/space/`：壁の実寸の絵、トリガーでリグが 1.2 秒接近 + ビネット、溶ける、平面 → 球面の変形、空間内の文字（Canvas）、視線の動きで流れが寄る、B / Y 長押しで戻る。**実機（Quest）未確認**
- 作品ページ：絵は JS を待たず表示、OGP、言語の自動判定（zh-TW → zh-Hant など）と切り替え、共有、10 言語の UI 文言。ページ用 JS 7.8KB gzip、体験バンドル 128KB gzip
- テスト：vitest 9 件、Playwright スモーク（物語モード ja / en、静止画、ギャラリー）、長時間スクリーンショット
- GitHub Actions（generate → test → build → Pages）

**決めた**
- 文字は troika ではなく、物語モードは DOM、VR は Canvas のスプライト（フォントの同梱なしで CJK が出る。S-2 の逃げ道を先に採用。troika は文字がにじむなら後で）
- 声は `<audio>` 要素、環境音は Web Audio（iOS の消音対策）
- 流体の初期速度の符号は低周波ノイズで滑らかに。渦度 ×6、流れ場の平滑化 σ=6、原画回帰 0.003（渦が細かくなりすぎて構図が崩れたため）

**困った・学んだ**
- `vite preview` にも basic-ssl が効いて HTTPS になり、スモークが通らなかった。`isPreview` で除外
- `pkill -f "vite preview"` や `fuser -k` が自分のシェルまで殺した。ポートの後始末は PID を見て個別に
- GitHub Pages の有効化は API がプロキシで拒否される。作家が Settings → Pages → Source: GitHub Actions にする必要がある
- SwiftShader（CPU 描画）では 90 秒で 20〜80 fps。実機の GPU なら十分速いはずだが、Quest は未確認

**次にやる**
- 作家：Pages を有効化、サブドメインの DNS、Harmoney の寸法・メッセージ・声、部屋の AI 画像、Quest で VR を試す
- Claude：Quest の結果を見て品質段階を調整。troika の検討。作品を増やす

## 2026-11-02（Day 0）

**やった**
- リポジトリ作成、計画ドキュメント一式（PLAN / ARCHITECTURE / WORK_FORMAT / SCHEDULE / RISKS）
- GitHub に public で公開：https://github.com/sheer-jp/enter-the-painting
- 作業ルーチン（ログ・レビュー・テスト）と `/log` `/close` `/dig` スキルを追加
- ユーザー理解の深掘り資料（`docs/USERS.md`）を追加

**決めた**
- 体験の核を確定：近づくと絵が流体になって全身を包む（S2〜S3）、奥から文字が浮く（S4）、文字は母語で自動選択（10 言語）。`docs/EXPERIENCE.md` に場面ごとの数値と受け入れ条件を書いた
- MVP は 5 作品。入口は会場の QR とオンラインギャラリーの 2 つ。作品ごとに固定ページ `/w/<id>/`
- 言語は選ばせず端末の言語で決める。理由は作家の言葉「母語でないと心にスッと入ってこない」
- NFC タグは将来項目。タグに同じ URL を書くだけなのでアプリ側の追加実装は不要
- three.js + Vite + TypeScript。流体は自前の GPU シム、文字は troika-three-text。UI フレームワークは入れない
- 画像解析はビルド時（`npm run generate`）に寄せ、実行時は `space.json` だけ読む
- 1 作品を VR まで通してから作品数を増やす。最低ラインは Day 3「Quest で入れる」

- 課題を「絵の『世界』が伝わらない場面が 3 つある（会場の小さな絵、オンラインの絵、買ったあとの絵）」と一言にした。オンラインで買う気持ちになれない問題にも効く（出会いの瞬間と作家の話を埋める。手触りは埋めない）。販売ツールに寄せない
- 計画を V2 に上げた（`docs/CHANGELOG.md`）。課題 3 場面（P1 会場の小さな絵、P2 オンラインの絵、P3 買ったあとの絵）に合わせて、要件定義 `docs/REQUIREMENTS.md` を新設
- VR は空間モード（ギュンと近づく 1.2 秒 → シュワシュワ 3 秒 → 包まれる 4 秒 → 文字と声）。PC・スマホは物語モード（拡大 → 溶ける → 流体のアニメーションと文字と声 → 絵に戻る、1〜3 分）。没入が無い環境で空間を歩かせても流体の意味が薄いため
- 作品ページに「部屋で見る」：AI 生成の部屋に実物の絵を実寸で合成。絵は生成モデルに入れない。各部屋に「小さな物語」（生活の中のアート、3〜5 文、10 言語）
- ギュンの速さは 1.2 秒を初期値にし、実機で微調整
- ユーザージャーニー `docs/JOURNEY.md` を書いた（5 つの旅と、設計で押さえる交差点 6 つ）
- 計画をさらに分解：`docs/TASKS.md`（日ごとのタスク、誰が、依存、完了条件）、`docs/SPIKES.md`（技術検証 8 つと逃げ道）、`docs/CONTENT.md`（作家が作るものの基準）、`docs/PITCH.md`（提出と動画の絵コンテ）、`docs/DECISIONS.md`（決定 12、未決定 11 に期限）。`docs/ARCHITECTURE.md` にモジュールの境界（TS のインターフェース）を追加
- 声は日本語のみで訳さない。日本語以外の人は、声は日本語のまま文字が母語（字幕の役割）

- 独立レビュー（サブエージェント）の 25 件を反映して V2.1 に。主な変更：公開を Day 1 に、独自ドメイン、フォールバック、数値拡散の対策、流体の領域を等距離円筒に、iOS の消音対策、VR の最低ライン検証を Day 1 に、落とすものの候補、権利表記。詳細は `docs/CHANGELOG.md`

**困った・学んだ**
- 自分が書いた計画を自分で見ると見落とす。独立レビューで、数値拡散（「拡散 0」で防げない）、球面の裏側に流れ込む先が無い、iOS の消音で Web Audio が鳴らない、公開が Day 5 では検証できない、が見つかった
- Claude が誤って `/dev/null` を削除するコマンドを混ぜ、git が止まった。`mknod -m 666 /dev/null c 1 3` で復旧。コマンドにゴミを混ぜない
- クラウドセッションから GitHub の新規リポジトリ作成はできない（セッションに紐づく repo 以外の API が拒否される）。repo は github.com/new で手動作成し、push は Claude が行う
- 自動許可モードでは外部アップロード系のコマンドが止まる。確認が必要な操作は「Accept edits」モードに切り替える

**次にやる**

- 部屋のイメージ 6〜10 枚を作る（作家の好きな画像生成ツールでよい。空いた壁、人や家具で大きさがわかる場面）
