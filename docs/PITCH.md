## 3. ピッチの構成（3 分）

1. **課題（30 秒）**：作家の言葉で。「大きな絵の前では人は入り込む。小さな絵では無理。オンラインではもっと無理。買ったあとはインテリアになる」。3 場面の表
2. **体験（60 秒）**：動画。VR で包まれる → スマホの物語モード → 作品ページの「部屋で見る」と物語
3. **自動化（30 秒）**：`works/<id>/` に画像とメッセージを置いて `npm run generate`。流れ場・10 言語・部屋の合成・QR が出るところを早回しで。「新作追加 10 分」
4. **Claude Code の使い方（30 秒）**：計画（USERS / EXPERIENCE / REQUIREMENTS）から実装、レビュー、ログまでの 1 週間の流れ。`docs/LOG.md` と `docs/CHANGELOG.md` を見せる。V1 → V2 で課題がどう深まったか
5. **証拠と次（30 秒）**：第三者テストの数値（没頭 1〜5、体験前後の「買いたい」）。次の個展で展示する。NFC、持ち主の記憶

## 4. デモ動画の絵コンテ（90 秒）

| 秒 | 映像 | 音・字幕 |
| --- | --- | --- |
| 0〜8 | 会場の壁の小品。手のひらと比べる | 「小さな絵では、絵の中に入れない」 |
| 8〜15 | スマホで作品カードの QR を読む。作品ページが開く | 「QR を読むと」 |
| 15〜35 | Quest の録画：壁の絵にトリガーでギュン → シュワシュワ → 包まれる → 文字が浮く → **戻ると壁の小さな絵に戻る（構図が残っている）** | 作家の声（実際のナレーション） |
| 35〜50 | スマホの画面録画：物語モード。流体の奥から文字（英語設定で英語） | 「スマホでは物語として。母語で」 |
| 50〜65 | 作品ページを下にスクロール：部屋で見る（6 枚）、小さな物語 | 「自分の部屋に置いたら」 |
| 65〜80 | ターミナル早回し：`npm run generate -- new-work` → 生成物が並ぶ → ギャラリーに 6 作目 | 「画像とメッセージを置くだけ」 |
| 80〜90 | 第三者が Quest を外して一言（実写）。公開 URL と QR | 「次の個展で」 |

録画：Quest はヘッドセットの録画機能（1 人称）。スマホは画面録画 + 手持ちの実写。編集は作家の好きなツール。

## 5. 審査で聞かれそうなこと

| 質問 | 答えの用意 |
| --- | --- |
| 絵を AI で変えているのでは | 変えていない。流体にして流すだけで、戻すと元の絵（動画で見せる）。部屋は AI 生成だが絵は実物の写真で、寸法は目安と明記 |
| AI ハッカソンなのに、実行時に AI は無いのか | 無い。AI は「作家の手作業を無くす」側にある。空間のパラメータ抽出、10 言語の翻訳、物語の下書き、部屋のイメージ、そして Claude Code による設計から実装・レビュー・ログまで。実行時に呼ばないのは速さ・費用・オフラインのため |
| よくある WebGL の流体デモと何が違う | 絵の具が流れても構図が残り、戻すと元の絵になる（MacCormack + 原画への回帰）。流体は目的ではなく「小さな絵の中に入る」ための手段 |
| VR 持っていない人は | スマホと PC の物語モード。会場の QR はスマホが前提。VR は会場に置いた Quest で順番に（U-14 の決定による） |
| 本当に没頭するのか | 第三者の記録（`docs/USERS.md`）。VR の「包まれた」1〜5 |
| 他の作家も使えるか | `works/<id>/` の定義ファイルだけ。10 分で追加 |
| 売上につながるのか | 連絡リンクの数と、体験前後の「買いたい」の差。販売機能は作らない方針 |
| Claude Code は何をした | 計画の深掘り（課題 3 場面、ジャーニー）、流体・WebXR・生成パイプラインの実装、レビューとログのルーチン |
