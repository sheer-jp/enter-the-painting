## 3. C 受付の画面

### 3.1 構成（スマホが基準。PC はその拡大）

```
┌─────────────────────────┐
│ ようこそ、SHEER のギャラリーへ   │ 見出し。明朝、小さく。英語は Welcome to SHEER's gallery。右上に言語
│                           │
│   [キャラクター 上半身]        │ 上。高さは画面の 32〜38%（スマホ縦）。紙の白。名前は小さく下に（空なら出さない）
│                           │
├─────────────────────────┤
│ 〔いらっしゃいませ。〕          │ 会話。キャラクターの文は左に吹き出し、自分の文は右。1 吹き出しずつ
│ 〔今日は、どんな絵をお探しですか？〕│
│                           │
│   ┌ 朝、静かに始めたい ┐       │ 3 つの選択肢（縦積み、タップ）。打ち始めたら消える
│   ┌ 夜、ひとりで息をつきたい ┐  │
│   ┌ 人を迎える部屋に彩りを ┐   │
├─────────────────────────┤
│ [ こんな気分のときに、こうしたい ] [送る] │ 入力欄。画面の下に固定。キーボードで会話が隠れない
└─────────────────────────┘
```

- **最初の 2 文は固定**（`recommend/config.json` の `greeting`）。API を待たず、0.4 秒ずつ間を置いて現れる
- **自由文が主、選択肢は添え物**。どちらも同じ会話に入る。選択肢は 1 往復目だけ出す（2 往復目以降は AI の問いに自由文で答える）
- **1 吹き出しずつ**。ストリーミングの文字はそのまま流す。文が来るまで「…」の 3 点をゆっくり明滅
- **表情**：3 枚の画像を切り替える。`listening`（相手が打っている・AI が考えている）、`smile`（AI の文が出ている）、`present`（おすすめを差し出した）。切り替えは 300ms のクロスフェード。`prefers-reduced-motion` では即時
- **おすすめ**：AI の最後の文のあと、会話の中に**絵のカード**が現れる（初めて絵が出る瞬間。扉が開くように、0.8 秒で下からふわっと）。カード：絵（実寸比）、題名、寸法、理由の 1 文、使ったことば（5 節の `matched_moods`）を小さく。ボタン「この絵を見に行く」（S0 へ `?via=concierge`）「ギャラリーを歩く」（G へ `?from=<id>`）。あるいはの 1 点は小さく下に
- **終わったあと**：入力欄は「もう一度、話す」に変わる。押すと会話が消えて最初に戻る
- **API が無い・失敗・拒否**：ルールだけの版（3 問の選択肢）を**同じ画面・同じキャラクター**で出す。見た目は変えない。失敗したことは言わない（「少し考えさせてください」程度）
- **合言葉（実験のあいだ）**：Function 側の `env.PASSPHRASE` が空でないとき、ブラウザは最初の送信の前に 1 回だけ「合言葉」を聞く（キャラクターが「ここは準備中の部屋なので、合言葉をいただけますか」）。入力は `X-Passphrase` ヘッダで API に添え、Function が比べて違えば 403。一致したら `localStorage` に覚える。違えば（または合言葉を持たなければ）ルールだけの版で会話する。ブラウザのコードに合言葉を置かない。合言葉が要るかどうかは、ページ読み込み時に `GET /api/recommend/config`（`{ passphrase: true|false }` だけ返す）で知る。`PASSPHRASE` は Pages の Secret。空なら照合しない
- 言語は端末の言語（既存の判定）。キャラクターの文は作家の言葉のトーン（説明しない、売り込まない、情景で話す）。会話は保存しない。名前や連絡先は聞かない

### 3.2 スマホの要件

- 縦 375×667（iPhone SE）で、キャラクター・最新の 2 吹き出し・入力欄が同時に見える。キーボードが出たら会話が入力欄の上に詰まり、最新の吹き出しが見える（`visualViewport` で高さを追う）
- 横向きでは、キャラクターを左 36%、会話を右に
- タップの的は 44px 以上。送信は Enter（PC）とボタン（スマホ）。`enterkeyhint="send"`。iOS で入力欄に寄ると拡大しないよう `font-size` は 16px 以上
- フォントの拡大（iOS の文字サイズ）で崩れない。`100dvh` を使い、`100vh` は使わない。`viewport-fit=cover` と `env(safe-area-inset-*)`
- 画像は `public/concierge/*.png` を 2 枚ずつ（1x 512px、2x 1024px）。`<picture>` で出し分け。合計 600KB 以下
- 受付のページ用 JS は gzip 25KB 以下（いまの 13.5KB + 受付の分）。体験バンドルは読まない

### 3.3 キャラクター

- 基準：`ai-dev/_meta/development/enter-the-painting/concept/concierge-v4/`（第 4 案：黒に寄せた髪、イラストのタッチ）。作家が最終確認するまでは第 3 案を仮置きし、画像を差し替えるだけで済むようにファイル名を固定する：`public/concierge/listening.png`、`smile.png`、`present.png`（+ `@2x`）
- 対応：`listening` ← 「首をかしげて聞く」、`smile` ← 「手を合わせて迎える」、`present` ← 「小さく手を上げる」
- 名前と口調は `recommend/config.json` の `persona`（`name`、`tone`、`intro_line`）。作家が直す。仮：名前は空（画面に出さない）、口調は丁寧で短い
- 画像は生成 AI（作家の絵は入れない）。`THIRD_PARTY.md` に生成手段を書く

## 4. G ギャラリー空間

- 白い壁（紙白 `#f6f4ef`、床線 1 本）。絵は実寸比（`--rel`）で間隔を空けて並ぶ。題名と寸法は絵の下に小さく
- **PC**：横に長い 1 枚の壁。横スクロール（スナップ）。マウスホイールの縦を横に流す
- **スマホ**：縦に並べる（横スクロールは親指に合わない）。1 画面に 1〜2 点。実寸比は保つ（小さい絵は小さく見えるが、最小幅 40% は確保）
- おすすめの 1 点（`?from=<id>`）が最初に来て、ほんの少し明るい（背景の光）。「あなたへの 1 点」と小さく
- 背景に部屋の写真は置かない（D5-2 取り下げ）
- VR（V1 以降）：同じ壁を 3D で。V0 はスクロールの壁だけ
- 絵を選ぶ → `/w/<id>/?via=gallery`
- ギャラリーの HTML も `generate` が作る（`gallery/index.html`。`pages.js`）。いまの `/` のギャラリーは受付に置き換える

## 5. 配線：作品のことば → カタログ → AI

受付が「あなたへの 1 点」を選べるのは、各作品に**ことば**があるから。鎖は次のとおり。どこか 1 つでも空だと、AI は色の軸だけで選ぶことになる。

```
docs/WORKS_VOICE.md           作家の語り（11-06 口述。原典）
        ↓ 作家のことばで整える（下書き → 作家が直す）
works/<id>/work.json          messages（作家の声、3〜5 行）、messages_en、moods（気分の言葉、3〜5 語）、moods.fit（向く人・時間、1 行）、note
        ↓ npm run generate
works/<id>/generated/space.json   messages（10 言語）、story
public/catalog.json               id、title、size、availability、palette、axes（warmth / brightness / energy）、moods、fit、messages、story
        ↓ Function が読む（10 分キャッシュ）
system プロンプト（functions/_lib/prompt.js の catalogText）
        ↓
ツール recommend_work（id は enum、reason、matched_moods）
```

V1 でやること（E-4）：

- **6 作品すべてに `moods` と `messages` を置く**。金沢展の 5 点は `docs/WORKS_VOICE.md` の語りから、作家の一人称で 3〜5 行に整える（先頭に `（下書き。作家が書き直す）`は付けない。語りが作家本人のものだから。ただし `note` に「11-06 の口述から整えた。作家が直す」と書く）。英語は `messages_en` に
- **`moods`**：各作品 3〜5 語。語りの中の言葉を使う（例：New Chapter「新しい章」「元気が出る黄色」「半立体のドット」）
- **`moods.fit`**（ja/en、1 行）：どんな人・どんな時間に向くか（例：「新しいことを始める朝に」）
- `catalogText` に `fit` の行を足す。system に「おすすめの理由は、その作品の moods か messages のことばを 1 つ以上使って書く」を足す
- `recommend_work` の入力に `matched_moods`（文字列の配列。選んだ作品の moods から 1〜3 語）を足す（strict）。カードの理由の下に小さく出す
- 翻訳（8 言語）は作家のキー付き `generate` で後から。V1 は ja / en

## 9. 受け入れ条件（V1）

1. `/` を開くと絵は出ず、見出し・キャラクター・最初の 2 文が 2 秒以内に出る（4G、JS 前に見出しとキャラクターは HTML で出る）
2. 自由文を 1 つ打つか選択肢を 1 つ押すと、キャラクターの問いが 1 吹き出しで返り、2〜4 往復で会話の中に 1 点のカードが現れる。理由の文に、その作品の `moods` か `messages` のことばが含まれる
3. API が無くても、同じ画面で 3 問の選択肢から 1 点に至る
4. 「ギャラリーを歩く」で白い壁に 6 点が実寸比で並び、おすすめの 1 点が最初。選ぶと S0。スマホは縦並び
5. `public/catalog.json` の 6 作品すべてに `moods.ja`（3 語以上）、`fit.ja`、`messages.ja`（3 行以上）がある
6. iPhone SE の縦でキャラクター・最新 2 吹き出し・入力欄が同時に見え、キーボードを出しても最新の吹き出しが隠れない
7. 会場の QR からの S0 は変わらない。スモークが通る。ページ用 JS は gzip 25KB 以下
