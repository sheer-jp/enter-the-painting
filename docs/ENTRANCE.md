# 入口の設計 V0：受付の会話 → ギャラリー → 絵の中へ（11-06、作家の構想を Fable が整理）

作家の構想（11-06）：「一番最初はチャットで始まる。LINE みたいに。ギャラリーオーナーのキャラクターが上にいて、ゲームみたいに下に会話があって、そこに『こういうのがいい』と打っていく。その裏に API がある。最初から絵がドーンと出る想定ではない。そこから入ると、白い背景のギャラリーっぽいところにいろんな絵があって、スクロールできたり、VR なら歩いていけたりする。そこで絵を選ぶと、絵の中に入れる。」

いまの `/`（宣言文 + 気分の入口 + 絵の壁）は、この構想とずれている。絵が先に出て、会話は脇役になっている。この文書は、入口を**会話が主役の受付**に作り直すための設計。`docs/RECOMMEND.md` の仕組み（カタログ、Worker、ルールだけの版、プロンプトの契約）はそのまま使い、**画面の順番と主従を変える**。

## 1. 誰のどの悩みに効くか（`docs/USERS.md`）

- **E オンラインで絵を見る人**：絵が並んでいても、どれが自分の絵かわからない。先に「自分のこと」を話してから絵に会うと、出てきた 1 点が「自分のためにある」と感じやすい（仮説 10）
- **B 来場者**：会場では作家が「どんな絵をお探しですか」と聞いてくれる。その接客をオンラインの最初に置く
- 受付を**先に**置く理由：人は「見せられた絵」より「自分の言葉のあとに出てきた絵」に心が動く。だから**会話のあとに絵が現れる**順番にする

仮説 11：受付の会話を通った人は、一覧から選んだ人より、絵の中に入ったあとの「買いたい」（1〜5）が高い。検証：`?via=concierge` と `?via=gallery` で入口を分け、体験後の 1 問で比べる（`docs/RECOMMEND.md` 5 節）。

## 2. 三つの場面

| # | 場面 | 見えるもの | やること | 次へ |
| --- | --- | --- | --- | --- |
| **C** | 受付（`/`） | 上にギャラリーオーナーのキャラクター、下に会話。絵は出ない | 気分や暮らしをひとこと打つ（または 3 つの選択肢をタップ）。2〜4 往復 | オーナーが 1 点を差し出す → 「この絵を見に行く」または「ギャラリーを歩く」 |
| **G** | ギャラリー（`/gallery/`） | 白い空間。絵が実寸比で長い壁に並ぶ。おすすめの 1 点が最初に来る（または光る） | 横にスクロール。VR では壁に沿って歩く | 絵を選ぶ → S0 |
| **S0** | 作品ページ（`/w/<id>/`） | いまのまま | 「入る」 | 物語モード / 空間モード |

- 会場の QR は**いまのまま S0 に直接着く**（受付を通らない）。受付はオンラインの入口
- C には「受付を飛ばしてギャラリーへ」の小さなリンクを置く（2 回目の人、急ぐ人）
- 絵の中（T0〜T5、S1〜S5）は変えない

## 3. C 受付の画面

建て付け（11-06 作家）：**「ようこそ、SHEER のギャラリーへ」**。ここは SHEER（アルファベット表記）のギャラリーで、来た人を迎える場所。最初の宣言文「小さな絵の、奥へ。」は使わない。

```
┌──────────────────────────────┐
│  ようこそ、SHEER のギャラリーへ        │  見出し。明朝、小さく。英語は Welcome to SHEER's gallery
│  [キャラクターの上半身。静止画。      │  上 40%。紙の白。
│   聞いている / 微笑む の 2〜3 表情]    │
├──────────────────────────────┤
│  いらっしゃいませ。                 │  下 60%。会話。キャラクターの文は左、自分の文は右。
│  今日は、どんな絵をお探しですか？      │  1 吹き出しずつ現れる。
│                                  │
│      [朝、静かに始めたい] [夜、ひとりで息をつきたい] [人を迎える部屋に彩りを]
│                                  │
│  ┌ こんな気分のときに、こうしたい ──┐ [送る]   自由に書ける入力欄。画面の下に固定
└──────────────────────────────┘
```

- **最初の 2 文は固定**（`recommend/config.json` の `greeting`。作家が直す）：「いらっしゃいませ。」「今日は、どんな絵をお探しですか？」。API を待たずに出す
- **自由文が主、選択肢は添え物**。「こういう気分のときに、こうしたい」を自分の言葉で書ける。3 つの選択肢（`openers`）はタップでも使える。どちらでも同じ会話に入る
- **ゲームの会話画面の作法**：キャラクターは上に固定、文は 1 吹き出しずつ（ストリーミングの文字をそのまま）。表情は返答の種類で切り替える（聞いている → 微笑む）。アニメーションは V0 では入れない
- **少しのゲーム性**：会話を進めると「扉が開く」ように絵が現れる。おすすめのカードが会話の中に出て、「この絵を見に行く」「ギャラリーを歩く」。あるいはの 1 点は小さく
- **会話の長さ**：2〜4 往復で必ずおすすめに至る（`docs/RECOMMEND.md` 8.5 の契約のまま）
- **API が無いとき**：ルールだけの版（3 問の選択肢）を**同じ画面・同じキャラクター**で出す。見た目は変えない
- 言語は端末の言語。キャラクターの文は作家の言葉のトーン（説明しない、売り込まない、情景で話す）
- 会話は保存しない。名前や連絡先は聞かない（`docs/RECOMMEND.md` 5 節）
- 既存の `src/recommend/`（会話、SSE、ルールだけの版、`parse.ts`）を土台にし、画面だけを作り直す

### キャラクター（方向は決定、最終案は作家が選ぶ。`docs/DECISIONS.md` U-12）

11-06 に 4 方向（作家の似姿 / 架空のオーナー / 猫のギャラリスト / 絵から生まれた存在）の候補画像を見て、作家が決めたこと：

- 架空のオーナーではない。**作家と来た人の間を取り持つ存在**。「ようこそ」と迎える
- **作家のメタファーの、小さな人間のキャラクター**。作家本人の似顔絵ではなく、雰囲気をぎゅっと小さくしたもの。質感はカップルウィッシュリストのマスコット（うさぎ）に寄せるが、動物ではなく人間
- **口を閉じて微笑む**。大きく笑わない。来た人が「作家に会えた」気持ちになり、もてなされていると感じること

画像は生成 AI で作る（作家の絵は入れない。`CLAUDE.md` の規則）。候補は `ai-dev/_meta/development/enter-the-painting/concept/`（第 1 案 4 方向、第 2 案 ポーズ違い 3 枚）。決まったら、同じキャラクターで表情・ポーズ 2〜3 枚、1:1、紙の白背景、`public/concierge/` に置く。VR では入口の壁にパネルとして置く（V1 以降）。

## 4. G ギャラリー空間

- 白い壁（`#f6f4ef` 程度の紙白、ヘアラインの床線 1 本）。絵は実寸比（いまの `--rel`）で、**横に長い 1 枚の壁**に間隔を空けて並ぶ。タイトルと寸法は絵の下に小さく
- PC・スマホ：横スクロール（スナップあり）。おすすめの 1 点から始まる。背景に部屋の写真は**置かない**（`docs/TASKS.md` D5-2 は取り下げ。U-13）
- VR（V1 以降）：同じ壁を 3D で。壁に沿って歩く（スティック移動）か、絵の前にワープ。酔い対策は `docs/EXPERIENCE.md` の方針のまま。V0 はスクロールの壁だけ
- 絵を選ぶ → `/w/<id>/?via=concierge|gallery`

## 5. API と置き場の提案（Fable）

### 5.1 どの API か

| 選択肢 | 向き・不向き | 判定 |
| --- | --- | --- |
| **Messages API（ストリーミング）** — いまの `worker/` | 2〜4 往復、道具（ツール）不要、会話はブラウザが持つ、1 回の応答が短い。最も軽く、最も安い | **これ**（継続） |
| Messages API + ツール `recommend_work`（`strict: true`） | 「文のあとに JSON を 1 つ」をテキストから拾う代わりに、おすすめを**ツール呼び出し**として受け取る。JSON の壊れが無くなり、型が保証される | **V1 で足す**（小さな変更） |
| Managed Agents（サーバー側で会話とサンドボックスを持つ） | 長い作業、ファイル、コード実行、予定実行向け。会話がサーバーに残る（「保存しない」方針と合わない）。往復ごとの待ちと費用が増える | 使わない |
| Claude Agent SDK（Claude Code をライブラリにしたもの） | 自分のサーバーで動く「コーディング・ファイル操作のエージェント」。受付の会話には道具が多すぎる | 使わない |
| 会話スレッド（`thread`、beta） | 往復ごとに送る量を減らす。会話が 4 往復なら効果は小さい | 当面不要 |

- **モデル**：開発中は `claude-sonnet-5-5`（作家の方針 11-05）。接客の質を上げるときは `claude-opus-5-5`。どちらも思考は常時オンなので `output_config.effort: "low"` で短く
- **費用の目安**（カタログ約 3,000 トークンを system に入れ、4 往復、プロンプトキャッシュあり）：1 会話あたり Sonnet で数円、Opus で十数円。作品が 20 点に増えてもカタログは 1 万トークン以下
- **拒否のとき**：いまの `fallbacks: "default"`（`server-side-fallback-2026-07-01`）のまま。それでも拒否ならルールだけの版へ
- 会話はサーバーに残さない。ログは状態コードだけ（いまのまま）

### 5.2 置き場：静的サイトと API を**同じ場所**に

いままで「うまくいかなかった」原因は、置き場が 3 つに割れていたこと：サイト本体（GitHub Pages → 上げない方針に変更 → 未定）、Worker（`enter.sheerarts.com/api/*` のルート。サブドメインの DNS が未設定）、キー（Worker の Secret）。サイトの origin が決まらないと Worker の CORS もカタログの URL も決まらない。

**提案：Cloudflare Pages に一本化する。**

- サイト本体：`dist/` を Cloudflare Pages に置く（git 連携で `main` の push → `npm run generate && npm run build`）
- API：`worker/src/` を Pages Functions（`functions/api/recommend.js`）に移す。コードはほぼそのまま（`fetch` で Claude API、SSE 中継）。同じ origin なので CORS もルートも不要。カタログは `./catalog.json` を同じ配信から読む
- キー：Pages の環境変数（Secret）に `ANTHROPIC_API_KEY`。リポジトリには書かない
- ドメイン：`enter.sheerarts.com` を Pages のカスタムドメインに（`sheerarts.com` は Cloudflare にあるので DNS は自動）
- 作家がやること：Cloudflare のダッシュボードで Pages プロジェクトを作って GitHub を繋ぐ（1 回）、Secret を貼る（1 回）、カスタムドメインを追加（1 回）。`wrangler login` は不要になる

代案：Vercel（作家の他のアプリと同じ場所）。静的 + `api/recommend` の Function で同じ構成が組める。DNS は Cloudflare 側で CNAME。Cloudflare で詰まり続けるなら移る。

## 6. 作品の中身（受付が成立する条件）

受付は**作品のことば**を頼りに選ぶ。金沢展の 5 点は `messages` と `moods` が空なので、いまのままでは Harmoney しか差し出せない。

- 作家：5 点それぞれに `messages`（3〜5 行）と `moods`（3〜5 語）を `works/<id>/work.json` に書く。1 点ずつでよい
- Claude：キー付きで `npm run generate`（8 言語の訳、小さな物語の下書き）

## 7. 作業の分担

| 誰 | 何を |
| --- | --- |
| 作家 | キャラクターの選定（候補画像を見て）、名前、5 点のことば、Cloudflare Pages の接続と Secret |
| Fable | この設計、受け入れ条件、レビュー、プロンプトの調整（6 作品で実際に会話して詰める） |
| Opus（Agent） | E-1 受付画面 `src/concierge/`（既存 `src/recommend/` を土台に）、E-2 ギャラリー空間 `/gallery/`、E-3 Worker → Pages Functions の移植とツール `recommend_work`、E-4 スモークの更新 |
| Codex | キャラクターの画像生成：候補 4 方向 → 選定 → 本番の表情 2〜3 枚（`public/concierge/`） |

受け入れ条件（V0）：

1. `/` を開くと絵は出ず、キャラクターと最初の問いが 2 秒以内に出る
2. 3 回タップ（またはひとこと打つ）で、会話の中に 1 点が現れる。API が無くても同じ画面で成立する
3. 「ギャラリーを歩く」で白い壁に 6 点が実寸比で並び、横にスクロールできる。選ぶと S0
4. 会場の QR からの S0 はいままで通り。受付を通らない
5. スモーク：受付（ルールだけの版）→ 1 点 → ギャラリー → S0 → 入る、が headless で通る

## 8. 決めてほしいこと（`docs/DECISIONS.md` U-12〜U-15）

1. **キャラクターは誰か**（3 節の 4 候補。候補画像を見て決める）
2. **名前と一人称**。会話の口調（丁寧か、親しいか）
3. **受付を必ず通すか**。「飛ばしてギャラリーへ」のリンクを置くか（置く案）
4. **置き場**：Cloudflare Pages 一本化でよいか（5.2）。だめなら Vercel
5. VR のギャラリー（歩く）は V1 に回してよいか（V0 はスクロールの壁）
