# 絵ごとの流体の性格（11-06 夜、Fable 設計）

作家の言葉（11-06）：「絵によって、絵の印象によって、流体の出方や波打ち方、細かさも違うはず。私が話した内容（`docs/WORKS_VOICE.md`）をもとに、それぞれの絵のコンセプトを理解・解釈した上で、アニメーションの出方や包まれ方を改善してほしい」。

いまは全作品が同じ既定（`restore 0.014`、`drive 0.3`、`tempo 0.6`、`look` 既定）で、`vorticity` と `speed` だけが色から自動で決まる。作品の**性格**が流れに出ていない。この文書は、語りから各作品の「流れの性格」を決め、`works/<id>/work.json` の `overrides` に落とす。数値は実機で作家が見て詰める（`docs/ROUTINE.md`「作品を追加するときのチェック」5）。

## 1. 性格を決める 6 つの軸（既存のパラメータに対応づける）

| 軸 | 何が変わるか | パラメータ（`overrides`） |
| --- | --- | --- |
| **速さ** | 流れの全体の速さ | `speed`（0〜1） |
| **渦の強さ** | 巻く・ほどける度合い。強いと渦が育つ | `vorticity`（0〜1） |
| **むら** | 速いところと溜まり、呼吸の振幅 | `tempo`（0〜1） |
| **戻る力** | 原画の構図にどれだけ早く戻るか。小さいと長く崩れる、大きいと構図が守られる | `restore`（0.005〜0.03） |
| **常時の駆動** | 止まらずに流れ続ける力 | `drive`（0.1〜0.6） |
| **細かさ** | 流れ場の平滑化。小さいと筆致の細部まで流れ、大きいと大きなうねり | `flow_sigma`（3〜10。生成時） |
| **質感** | 厚み（relief）、つや（gloss）、鮮やかさ（vivid）、粒（grain）、にじみ（bloom） | `look.*`（`docs/FLUID_LOOK.md`） |
| **包まれ方** | 球の半径（近いほど包まれる）、溶け始める距離 | `radius_m`、`melt_distance_m` |

新しく足す軸（実装 F-1）：

- **波打ち `swell`**（0〜1、既定 0）：低周波の面の起伏。厚み（`uThick`）に、ゆっくり動く大きな波（波長は領域の高さの 0.4〜0.8 倍、周期 9〜15 秒）を足して、光沢が波のように走る。半立体の絵（New Chapter）や厚塗り（頂）では、この波で表面の盛り上がりが見える。`look.swell` として `shading.ts` に
- **粒立ち `dots`**（0〜1、既定 0）：流れに乗る小さな丸い盛り上がり（半立体のドット）。`relief.png` の局所的な山を強調し、流れても形が残るよう `restore` を局所的に強める。New Chapter 専用に近い。`look.dots`
- **にじみ `bleed`**（0〜1、既定 0）：色の境界がゆっくり溶け合う（和紙ににじむ）。拡散は 0 の規則があるので、**色の拡散ではなく**表示側で境界を柔らかく見せる（`sharpness` を下げ、`bloom` を上げる組み合わせを 1 つの軸にしたもの）。`look.bleed`

| 作品 | 語りの芯 | 流れの性格 | `overrides` の初期値 |

新しく足す（実装 F-2）：**`drive_dir`**（`[x, y]`、既定なし）。常時の駆動の目標の流れに、一定の向きの成分を足す（頂は上へ。0.3 程度の重み）。`docs/EXPERIENCE.md` 8.1 の駆動の仕組みに「向き」を足すだけ。

## 3. 守ること（`CLAUDE.md`）

- 絵を変えない：拡散 0、色の減衰 0。`bleed` は表示側だけ
- MacCormack と原画への回帰を外さない。`restore` を小さくしても 3 分後に構図が残る（`tests/longrun.mjs` で各作品 3 分）
- 性能：Quest 72fps。`swell` と `dots` は表示シェーダの数行で済ませ、シミュレーションのパスを増やさない
- 両モードで同じ API（`fluid/`）。モードで分岐しない

## 4. 進め方

- **F-1**：`look.swell` / `look.dots` / `look.bleed` を `shading.ts` と `WORK_FORMAT.md` に足す（Opus）
- **F-2**：`drive_dir` を `Fluid.ts` の駆動に足す（Opus）
- **F-3**：6 作品の `overrides` を 2 節の初期値で置き、`generate`、`longrun` を 6 作品で回す（Opus）。各作品 30 秒・60 秒・180 秒のスクリーンショットを `evidence/fluid/` に
- **F-4**：作家が PC で 6 作品を見て、1〜5 で評価（`docs/USERS.md` の記録欄）。詰めた値と理由を `docs/LOG.md` に（作家 + Fable）

受け入れ：6 作品を並べて 30 秒見たとき、第三者が「それぞれ流れ方が違う」と言える。New Chapter は「跳ねる」、花は「滲む」、頂は「上へ渦巻く」と言葉にできる。

## 5. 11-06 夜の判断（作家）と追加の軸

- **頂は渦になってよい**。「渦になっていくのはエネルギーがあっていい。バーッと渦になってから、緩やかに落ち着いて、元の頂に静かに戻る」→ 新しい軸 **`arc`（時間の弧）**：T3 のあいだ、最初は全力（速さ・駆動・渦そのまま）、`peak_s` を過ぎたら `calm_s` までにゆっくり落ち着き（速さ ×0.45、駆動 ×0.4、戻る力 ×2.5 へ ease-in-out）、構図が静かに戻る。`overrides.arc: { "peak_s": 60, "calm_s": 150 }`。無ければ従来どおり一定。頂の速さは 0.8、駆動 0.5 に戻し、`arc` で落ち着かせる（F-5）
- **New Chapter のドットの層はほしい。ただし小さく**（作家「本気で書きすぎ。10〜20 分でできることで」）→ VR 用に作った粒（`src/space/Particles.ts`）を物語モードにも載せる最小版：`look.dots > 0` の作品だけ、`relief.png` の山の位置に丸い粒（主要色の明るい色、20〜40 個）を置き、流体の速度に乗せて流す。新しい仕組みは作らず、既存の粒の層の流用で済ませる（F-6）
- VR の床の反射は本当の床（足元）に置く。粒の見え方は作家が Quest で判断（V-5）
