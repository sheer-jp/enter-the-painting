# コンセプトの整理（2026-11-07、作家の言葉から）

**名前は「絵と出会う / Meet the Painting」に決定**（11-07 作家）。URL は https://meet.sheerarts.com 、GitHub は sheer-jp/meet-the-painting。

## 1. 大きな問題（これを最初に出す）

**作家がいない場所で、絵の魅力を伝えるのは難しい。**

- 展示の現場で、作家が在廊していないとき
- オンラインで絵を販売するとき

## 2. 見る人の側の問題

抽象画は、どう見ていいのか、何が魅力なのかがわかりにくい。だから「なんとなくいいな」と、**家具を選ぶように**選びやすい。

本当は、込められた思いに共感して、**長く自分の家で見ていける一枚**を見つけてほしい。

## 3. 解き方

個展で作家がしていることを、オンラインで受け持つ。

| 個展での作家 | このサービス | 機能 |
| --- | --- | --- |
| お客さまの話を聞いて、絵をすすめる | **出会う** | 案内役との会話 |
| この絵に込めた思いを語る | **知る** | 作品の一文、作家の言葉 |
| 絵の前で一緒に過ごす | **浸る** | 絵の世界（流体、VR） |
| 「お部屋のどこに飾りますか」と話す | **暮らしを想像する** | 部屋で見る、絵を動かす |

**案内役と絵の世界は同じ重さ。** 絵の中に入ることは手段のひとつで、目的ではない。

## 4. 伝え方の決まり

- 作品名だけでは伝わらない。作品名を知っているのは作家だけ。必ず「**この絵はこういう絵です → だからこう動きます**」の順で書く（`work.json` の `statement`）
- 技術の工夫（流れ場、構図が残る、MacCormack など）は、聞かれたら答える。先に言わない
- できないことをボタンや文にしない（`docs/RECOMMEND.md` 10 節）
- 日本語は普通の文で書く。読点で区切った断片、体言止めの連続、ダッシュ、詩のような言い回しを避ける

## 5. 名前（提案）

既に `gallery.sheerarts.com` は「SHEER GALLERY」（歩ける VR の展示室、`apps/vr-gallery`）が使っている。同じ名前を別のものに付けると混ざる。

| 案 | 名前 | 向き | 懸念 |
| --- | --- | --- | --- |
| **A（推し）** | **絵と出会う / Meet the Painting** | 「自分の好きな絵に出会う」にそのまま重なる。何をする場所かが初見でわかる | 浸る側の色は弱い（説明文で補う） |
| B | あなたの一枚 / Your One Painting | 買う人の気持ちに近い。「今日のあなたへの 1 点」と揃う | 売り場に見えやすい |
| C | 絵の世界に浸る / Into Its World | 作家の言葉に近い | 案内役が消える。Enter the Painting と同じ問題 |

SHEER Gallery は傘の名前として残す（画面の見出しはそのまま）。

## 6. URL と GitHub（提案）

| 対象 | いま | 提案 | 手間と影響 |
| --- | --- | --- | --- |
| 公開 URL | **https://meet.sheerarts.com**（11-07 開通） | — | サブドメイン。`lyric.` `pulse.` `timer.` と同じ形。古い pages.dev も動き続ける |
| Pages のプロジェクト名 | enter-the-painting | **変えない** | 改名の機能が無く、作り直しになる（鍵と KV の再設定）。公開 URL を替えれば見えない |
| GitHub | sheer-jp/meet-the-painting（11-07 改名済み） | — | 古い URL は GitHub が転送する。手元のフォルダ名は apps/enter-the-painting のまま |
| QR | meet.sheerarts.com 宛てに作り直し済み | — | `BASE_URL=https://meet.sheerarts.com npm run generate` |

提出フォームに既に URL を登録しているなら、古い URL が動き続けるので壊れない。
