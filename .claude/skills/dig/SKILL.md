# /dig

`docs/USERS.md` を土台に、いま決めようとしている体験や機能を「誰のどの悩みに効くか」から見直す。

## 使い方

`/dig <検討したいこと>`。例：`/dig ダイブ演出の長さ`、`/dig 来場者テストの結果`、`/dig 引数なし`（全体の見直し）。

## 手順

1. `docs/USERS.md` と `docs/PLAN.md` の「誰の、どんな困りごと」を読む
2. 検討対象について、次の 4 つに答える。答えは短く、仮説には「（仮説）」と付ける
   - **誰の悩みか**：A 持ち主 / B 来場者 / C 作家 のどれか。複数なら主を 1 つ決める
   - **その悩みのどの部分に効くか**：対応表の行を指す。該当行が無ければ、新しい悩みか、悩みに効かない機能のどちらか
   - **効かないなら**：やめる、または「やれたらやる」に下げることを提案する
   - **確かめ方**：どの質問（5 分インタビュー）か、どの数値で検証できるか
3. ユーザーテストの結果を渡されたときは、発言をそのまま記録欄に書き、「検証したい仮説」のどれを支持 / 否定するかを判定し、検証済みなら「わかったこと」に移す
4. 新しい悩みや登場人物が見えたら、`docs/USERS.md` に追記する。作家の言葉を言い換えず、そのまま引用する
5. 結論を「誰の・どの悩みに・こう効く・こう確かめる」の 1 段落で返し、`docs/USERS.md` を更新した箇所を示す

## 守ること

- 技術の都合から逆算して悩みをでっち上げない。効かないなら効かないと言う
- 「新しい体験」は、悩みが解けたあとに相手がどう変わるかで書く（例：「絵を持つ」が「絵の世界を持つ」に変わる）
